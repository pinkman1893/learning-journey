# 前端设计模式

## 什么是设计模式

设计模式是在软件设计中为解决常见问题而总结出的通用方案。

- 是历史经验的总结。
- 与特定语言无关。
- 是一种思维模式和方法论，而不是一种具体的实现方法。
- 能够提高系统的可维护性、可扩展性和可复用性。

## 设计模式的分类

- **创建型模式（Creational Patterns）**：关注如何创建对象。
- **结构型模式（Structural Patterns）**：关注如何将对象组合成更复杂的结构。
- **行为型模式（Behavioral Patterns）**：关注对象之间的职责分配和高效通信。

## 浏览器中的设计模式

### 单例模式

- **定义**：全局唯一访问对象。
- **应用场景**：缓存、全局状态管理等。
- **前端应用**：浏览器提供的 `localStorage` 和 `sessionStorage` 都可以作为全局访问的存储对象。`localStorage` 可以在同源的不同标签页间共享数据；`sessionStorage` 通常只在当前标签页的会话中有效。

### 发布—订阅模式

- **定义**：一种订阅机制，可在被订阅对象发生变化时通知订阅者。
- **应用场景**：从系统架构之间的解耦，到邮件订阅、上线订阅等业务实现，应用广泛。
- **前端应用**：DOM 事件系统中，事件源可以将事件广播给所有订阅该事件的监听器。这种解耦设计使系统可以灵活添加和移除事件监听器。

## JavaScript 中的设计模式

### 原型模式

- **定义**：复制已有对象来创建新的对象。
- **应用场景**：JavaScript 中对象创建的基本模式。
- **JavaScript 应用**：对象通过原型链继承属性和方法。通过修改对象的原型，可以实现对象的继承和扩展。

### 代理模式

- **定义**：自定义控制对原对象的访问方式，并允许在更新前后进行额外处理。
- **应用场景**：监控、代理工具、前端框架实现等。
- **前端应用**：代理模式常用于数据绑定和状态管理。例如 Vue 3 使用 `Proxy` 拦截对象的读写操作，实现视图和数据的响应式更新。

### 迭代器模式

- **定义**：在不暴露数据内部结构的情况下访问集合中的数据。
- **应用场景**：为列表、树等不同数据结构提供通用的遍历接口。
- **JavaScript 应用**：`for...of` 和 `Array.prototype[Symbol.iterator]` 允许开发者遍历数组、字符串等数据结构，而不需要暴露底层数据结构。

## 前端框架中的设计模式

### 代理模式

代理模式在前端框架中常用于拦截对象访问和实现响应式能力，例如 Vue 3 使用 `Proxy` 追踪数据读写；React 的状态更新机制不以 `Proxy` 为基础。

### 组合模式

- **定义**：既可以组合使用多个对象，也可以独立使用单个对象。
- **应用场景**：DOM、前端组件、文件目录和部门结构等。
- **前端应用**：React 可以通过组合多个子组件构建复杂界面，每个子组件又能独立工作。这种“组合”的思想是典型的组合模式应用。

## 总结：设计模式并不是万能的

- **根据场景选择**：设计模式并不是放之四海而皆准的方案，需要根据具体场景判断是否适用。
- **抽象模式不等于具体实现**：设计模式是对问题的抽象，不是直接可执行的代码，实际应用需要经验和判断力。
- **多编程范式的融合**：现代 JavaScript 支持面向对象、函数式等多种编程范式，为设计模式提供了更多灵活性。
- **不断实践和学习**：通过代码实践和阅读优秀开源项目，逐渐理解何时以及如何使用设计模式。
