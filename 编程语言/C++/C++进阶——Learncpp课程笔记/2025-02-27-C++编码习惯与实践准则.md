# C++ 编码习惯与实践准则

1. 声明变量后初始化
2. `cout`结束后跟上`<< endl;`或`\n`
3. 一般情况下使用`\n`性能优于endl
4. 分模块写程序，确保一个模块能编译、无错误、功能正常再去写下一个模块
5. 写完代码后进行二次修正、优化、整理、注释
6. **DRY：**”Don't Repeat Yourself！“——不要让多次重复的工作多次写独立的代码运行【模块化编程的核心原则】
7. 一个函数只完成一个工作，不要让一个函数变得太长太复杂，如果太长（5——7行为佳）则需要进行函数重构（refactor）
8. 不要重新排序函数，要使用函数声明
9. 在函数声明中保持参数名
10. 后期开发中尽量不使用`using namespace std;`，改用`std::`前缀【<font style="color:#DF2A3F;background-color:#FBDE28;">自己定义的标识符会跟 std 命名空间中的标识符相冲突，这与 namespace 的发明意图恰恰背道而驰！！</font>】
11. 将头文件命名为`XXXX.h`，如果一个头文件与某个代码文件配对，则命名为相同名称
12. 头文件引入顺序：（各自里面按字母排序）
    1. 与源代码配对的头文件
    2. 来自同一项目下的其他头文件
    3. 第三方库
    4. 标准库
13. 正常情况下不使用`unsigned`符号（非正常：位操作、嵌入式等）
14. 定义常量尽量使用`const`关键字，而不用`#define`宏定义
15. 使用后缀时用`L`，不用`l`
16. 常量声明的使用：
    1. 若常量变量初始化的值是能在编译时就确定的常量表达式：使用`constexpr`修饰
    2. 若初始化的值是必须在运行时才能确定的非常量表达式：使用`const`修饰
17. 如果`cin` 和 `getline()`出现混用的情况，给每个`getline()`加上 `ws`：`getline(cin >> ws,str);`
18. 较大的 `string` 参数通常优先通过 `const` 引用或 `string_view` 传递；返回 `string` 值通常可以利用复制消除或移动语义，不必一概避免
19. 当类型是字符串的对象只需要被读取而不需要修改时，使用`string_view`而不是`string`（不用复制操作）
20. 无论有没有必要，面对多重复合运算式时都使用`()`来表示优先级
![](assets/207842867/c4de7795c8d3.png)
21. 没有特殊需要的情况下，使用前缀自增自减符，性能更高
22. 对于浮点数，慎重使用`==`or`!=`【尤其是被运算而出现舍入误差时】
23. `&&`和`||`混合在一条语句中使用时一定要打`()`，`&&`的优先级更高
