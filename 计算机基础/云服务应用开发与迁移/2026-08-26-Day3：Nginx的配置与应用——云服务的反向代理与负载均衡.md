# Day3：Nginx的配置与应用——云服务的反向代理与负载均衡

## 反向代理 Reverse Proxy

### 作用

客户端不直接访问真正的后端服务器，而是先访问 Nginx，由 Nginx 将请求转发给后端服务器。

客户端只知道访问的 Nginx 地址，而不知道后端服务运行在哪里。

### “反向”概念

普通的代理行为通常代理客户端，例如 Clash 等网络代理工具；Nginx 代理的是服务器一侧，因而称为反向代理。

## 负载均衡 Load Balancing

当 Nginx 所代理的后方有多个服务器时——既可以是多台服务器，也可以是在同一台服务器上启用的多个实例，即服务节点——Nginx 可以把不同的客户端请求按需分配给不同服务器。

![](assets/282745845/1ef0f3e1d8f3.png)

多个服务器共同承担访问流量与资源消耗，而不是将压力集中在一台服务器上，以实现负载均衡。

在其中一台服务器出现故障时，Nginx 也可以将请求路由到正常的服务器，以增加服务可用性。

## Nginx 配置文件

Nginx 的核心配置文件为 `nginx/conf/nginx.conf`，可以在其中配置具体的反向代理和负载均衡策略。

- 可以在服务器上使用 `vim /www/server/nginx/conf/nginx.conf` 修改。
- 也可以直接在宝塔面板中修改：`软件商店 → 已安装 → Nginx → 设置 → 配置修改`。

![](assets/282745845/b52f113b7470.png)

### 核心配置体

```nginx
http {
    upstream mysites {
        # 定义“后端服务器有哪些”
        ...
    }

    server {
        # 定义“Nginx 怎么接收和转发请求”
        location / {
            ...
        }
    }
}
```

### 配置后端服务器池 `upstream`

```nginx
upstream mysites {
    server 192.168.133.157:8080 weight=3;
    server 192.168.133.1:8081 weight=7;
}
```

- `mysites` 为定义的后端服务器池名称。
- 服务器的定义格式为：`server IP地址:端口号 weight=接受请求的权重`。

### 配置用户请求转发 `proxy_pass`

```nginx
location / {
    proxy_pass http://mysites/;
}
```

- `location /`：表示匹配以 `/` 开头的用户请求。
- `proxy_pass http://mysites/;`：表示将请求代理给创建的 `mysites` 服务器池。

> `proxy_pass` 末尾的 `/` 可以省略，但两种写法的 URI 转发规则不同：带 `/` 时会使用指定 URI 替换匹配到的 `location` 前缀；不带 `/` 时通常保留原始请求 URI。

## Nginx 常用命令

- 启动 Nginx 服务：`nginx`
- 检查配置文件是否有错误：`nginx -t`
- 停止 Nginx 服务：`nginx -s stop`
- 安全停止，等待当前已有请求处理结束后再停止：`nginx -s quit`
- 重新加载配置：`nginx -s reload`
