# Week1：Java Web 技术演进与单体应用基础

> 学会问为什么。
>
> 学习组件、技术栈等不能只学习如何用；应该从共通的解决问题上入手，找到该方案、技术的独特性、优越性——即我们为什么要用……，用它解决了……

## 本周提到的相关技术栈与概念

### Servlet

#### 是什么

早期 Java Web 中用于处理 Web 请求的一套规范和机制。

#### 为什么出现

Java 程序需要统一处理客户端请求并返回响应。

#### 解决什么

处理 Request，生成 Response。

#### 课程目前怎么理解

Request → Servlet → Response

### Tomcat

#### 是什么

Servlet 容器的一种实现产品。

#### 为什么出现

Java Web 程序需要一个运行和管理 Servlet、接收 HTTP 请求的环境。

#### 解决什么

接收请求、管理 Servlet、返回响应。

### Struts

#### 是什么

早期 Java Web 开发使用的一类框架。

#### 为什么出现

直接编写大量 Web 处理方法会产生重复代码，需要进行统一封装。

#### 解决什么

规范和简化 Web 请求处理。

#### 课程目前怎么理解

Servlet 等基础方式 → 进一步封装 → Struts 框架

### JDBC

#### 是什么

Java 程序访问数据库的一套方式。

#### 为什么出现

程序需要把运行过程中产生的数据保存到数据库。

#### 解决什么

让 Java 程序能够连接和操作数据库。

#### 课程目前怎么理解

Java 程序 → JDBC → 数据库

### MyBatis

#### 是什么

用于简化数据库操作和数据持久化的框架。

#### 为什么出现

直接使用 JDBC 操作数据库代码较繁琐，需要进一步封装。

#### 解决什么

简化 Java 程序访问数据库的过程。

#### 课程目前怎么理解

Java 对象 → MyBatis → 数据库

### Spring

#### 是什么

用于管理程序中对象的框架。

#### 为什么出现

程序运行过程中会产生大量对象，需要统一创建和管理。

#### 解决什么

管理程序中的对象以及对象之间的关系。

#### 课程目前怎么理解

程序产生对象 → Spring 统一管理

### Spring MVC

#### 是什么

Spring 体系中用于 Web 请求处理的框架。

#### 为什么出现

Web 应用需要统一接收客户端请求，并将请求交给对应的业务代码处理。

#### 解决什么

负责 Web 请求接收、路由和响应处理。

#### 课程目前怎么理解

Request → Spring MVC → 对应业务处理 → Response

### SSH

#### 是什么

早期 Java Web 开发中多个框架组合形成的一套技术组合，意为 Struts + Spring + Hibernate 持久化框架。

#### 为什么出现

Web 请求处理、对象管理、数据持久化需要不同框架共同完成。

#### 解决什么

把多个框架组合起来完成完整的 Java Web 开发。

#### 课程目前怎么理解

Struts + Spring + Hibernate 持久化框架 → Java Web 应用

### Spring Boot

#### 是什么

用于简化 Spring 应用搭建和运行的框架。

#### 为什么出现

传统 Spring Web 项目需要组合和配置多个组件，搭建过程较繁琐。

#### 解决什么

把常用组件组合起来，减少项目搭建和配置工作。

#### 课程目前怎么理解

Spring Boot → Spring MVC + 内嵌 Tomcat

### Maven

#### 是什么

Java 项目中常用的项目管理工具。

#### 为什么出现

Java 项目需要统一管理项目结构和依赖。

#### 解决什么

管理项目文件结构、依赖和构建过程。

#### 课程目前怎么理解

Java 项目 → Maven 管理 → 构建运行

### JDK

#### 是什么

Java 程序开发和运行所需要的基础环境。

#### 为什么出现

Java 代码需要对应环境进行编译和运行。

#### 解决什么

提供 Java 程序开发和运行所需的基础能力。

#### 课程目前怎么理解

Java 项目 → 对应版本 JDK → 编译和运行

### Hibernate

#### 是什么

用于 Java 数据持久化的 ORM 框架。

#### 为什么出现

直接使用 JDBC 操作数据库需要编写较多数据库访问和对象转换代码。

#### 解决什么

通过对象与数据库数据之间的映射，简化数据持久化操作。

#### 课程目前怎么理解

Java 对象 → Hibernate → 数据库

## Java Web 后端框架发展演进

> Web 应用的常见结构是 B/S 架构，Browser 负责用户交互和内容展示，Server 则负责接收请求、处理业务、返回结果。

### 早期 Java Web：Servlet 与 Tomcat

早期 Java Web 主要依赖 **Servlet** 处理请求，由 **Tomcat** 作为 Servlet 容器负责加载和运行 Servlet。

特点：开发较为直接，Web 请求处理与配置等都需要开发者手动处理。

缺点：随着项目功能复杂，代码和配置越来越多，难以管理开发。

### 开始框架化：Struts 2 + JDBC / Hibernate

开始使用 Web 框架统一处理请求：**Struts 2** 将原来直接操作 Servlet 的方式进一步封装，通过 Action 等方式组织业务处理；与此同时，程序还需要解决数据持久化问题：

- **JDBC**：直接访问和操作数据库。
- **Hibernate**：进一步封装数据库操作，通过 ORM 建立 Java 对象与数据库数据之间的映射。

特点：使用框架开始分工，减少重复代码。

缺点：XML 配置依旧复杂繁琐。

### SSM 分层开发：Spring MVC + Spring + MyBatis

Java Web 继续发展后，逐渐形成更清晰的分层开发方式，典型组合为：Spring MVC + Spring + MyBatis，三者分别承担不同职责：

- **Spring MVC**：负责 Web 请求和 Controller 层。
- **Spring**：负责对象创建、管理和对象之间的关系。
- **MyBatis**：负责数据持久化和数据库访问。

项目结构逐渐形成：Controller → Service → DAO

特点：`@Controller` 等注解大量代替 XML 配置，框架之间的职责更清晰明确，项目形成规范的分层结构。

### 自动配置与一体化：Spring Boot

Spring Boot 在原有 Spring MVC、Spring、Tomcat 技术基础上做了进一步整合和简化。

特点：减少了大量 XML 配置，常用 `application.properties` 或 `application.yml` 进行配置，并通过自动配置和内嵌 Tomcat 大幅简化 Java Web 项目的搭建和运行。

## 单体应用

### 单体设计思路

需求 → 模块 → 功能 → API → 具体实现

即：一个产品先有**需求**，而后根据需求继续拆成各个**模块**，每个模块下继续拆成具体实现的**功能**，考虑功能真正实现需要什么，就会进入 **API** 的设计中，最后落实到**具体实现**。

### API 核心要素（以登录为例）

- 地址：`/login`
- 输入：用户名、密码
- 输出：登录成功 / 失败

---

API 设计思路：地址 → 输入 → 业务处理 → 输出

**业务决定了技术和功能如何选型和实现，而不是技术决定业务。**

> 业务并非只是增删改查 CRUD，CRUD 只是业务的一部分，业务处理需要真正理解功能、API；再根据业务需求去进行技术选型。

### 单体应用的局限

当单体应用的模块越来越多，会出现如下局限：

- **耦合度越来越高**：模块之间的依赖程度越来越高，关系越来越紧密；而系统设计应该实现的是“高内聚，低耦合”——即模块内部处理的事情尽量放在一起，模块之间尽量减少不必要的依赖。
- **扩容不灵活**：由于所有模块都打包、运行在同一个整体里，当整个系统的服务器的其中一个模块运行压力大时，我们期望复制一份到其他服务器上分担压力，但实际只能把整个捆绑的单体应用完整复制一份，进而造成资源浪费。
- **更新小功能代价大**：如要更新单体系统中的一个小模块中的小功能，需要将完整的单体应用打包、重新部署。
- **单进程问题**：单体应用的模块很可能都运行在一个进程中，若出现一个严重 Bug 导致进程出问题，全部模块都将不可用，整个应用都可能停止。

---

因而，开始考虑引入微服务：从系统往下不断拆分成模块、功能的思想发展到了：反过来看用多个独立的模块相加实现一个系统。

### Java 单体应用搭建示例

#### 开发环境：JDK

环境不应一味追求最新版本，而应该重视**稳定性、兼容性、是否满足自身需要**。

#### 脚手架：Spring Boot

脚手架，即为根据预设的结构框架，快速生成项目的骨架，而无需从 0 开始。

#### 项目与依赖管理及构建工具：Maven

Maven 是常见的 Java 项目管理、依赖管理与构建工具。

#### Spring Boot 配置文件

Spring Boot 项目常见两种配置文件形式：`application.properties`（以 Key-Value 呈现）、`application.yml`（以数据方式呈现）。

两者都用于保存应用运行所需要的配置信息，例如端口、数据库连接、服务相关参数等。
