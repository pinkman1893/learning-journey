# HTTP 协议使用指南

HTTP（HyperText Transfer Protocol，超文本传输协议）用于客户端（如浏览器）与服务器之间的通信，是 Web 的基础协议，支持客户端与服务器之间的数据交换。

## HTTP 的基本特点

- **应用层协议**：HTTP 属于 OSI 模型的应用层。HTTP/1.1 和 HTTP/2 通常运行在 TCP 之上；HTTP/3 则运行在基于 UDP 的 QUIC 之上。HTTP 默认端口为 `80`。
- **无状态协议**：每次请求相互独立，服务器不会仅凭 HTTP 协议记住之前的请求。通常使用 Cookie、Session 等机制维持状态。
- **请求—响应模型**：HTTP 采用请求—响应模型；底层连接是否复用取决于协议版本和配置。HTTP/1.1 默认支持持久连接，不一定在每次请求后断开。

## HTTP 请求和响应模型

客户端向服务器发送请求，服务器返回响应。

- **HTTP 请求**：由客户端发起，包含请求行、请求头和可选的请求体。
- **HTTP 响应**：由服务器返回，包含状态行、响应头和可选的响应体。

### 请求结构

- **请求行（Request Line）**：由请求方法、请求 URI 和 HTTP 版本组成，例如 `GET /index.html HTTP/1.1`。
- **请求头（Request Headers）**：包含客户端环境信息，如浏览器类型、操作系统和接受的响应格式等。
- **请求体（Request Body）**：可选，包含客户端发送到服务器的数据，通常在 POST 或 PUT 请求中使用。

### 响应结构

- **状态行（Status Line）**：由 HTTP 版本、状态码和状态消息组成，例如 `HTTP/1.1 200 OK`。
- **响应头（Response Headers）**：包含服务器信息、响应内容类型和缓存策略等。
- **响应体（Response Body）**：可选，包含 HTML、JSON、图片等实际返回内容。

## HTTP 请求方法

### GET

- **作用**：请求指定资源的表示形式。
- **用途**：获取数据，不应产生副作用，例如获取页面或图像。
- **特点**：通常用于读取资源，数据附加在 URL 后面，通过查询字符串传递参数。

### POST

- **作用**：提交数据，通常用于创建或更新资源。
- **用途**：提交表单、上传文件等，可能导致服务器状态变化。
- **特点**：数据通常放在请求体中，适合提交较多内容。

### PUT

- **作用**：用请求体中的数据替换指定资源的当前表示。
- **用途**：更新资源。
- **特点**：如果资源不存在，服务器可能创建该资源。

### DELETE

用于删除指定资源。

### HEAD

与 GET 类似，但不返回响应体，通常用于获取文件大小、最后修改时间等资源元数据。

### CONNECT

建立到指定资源的隧道连接，常用于代理服务器，例如通过代理建立 HTTPS 加密连接。

### OPTIONS

请求目标资源支持的通信选项，例如支持的 HTTP 方法。

### TRACE

沿着到目标资源的路径执行消息环回测试，回显服务器收到的请求，通常用于诊断和调试。

### PATCH

用于对资源进行部分修改。与 PUT 相比，PATCH 通常只提交需要修改的部分。

## HTTP 状态码

### 1xx：信息性状态码

- **100 Continue**：请求已接受，客户端应继续发送请求的其余部分。

### 2xx：成功状态码

- **200 OK**：请求成功，服务器已成功处理。
- **201 Created**：请求已完成，资源已创建。
- **204 No Content**：请求成功，但没有响应体返回。

### 3xx：重定向状态码

- **301 Moved Permanently**：资源已永久移动到新的 URI。
- **302 Found**：资源临时移动到另一个 URI。

### 4xx：客户端错误状态码

- **400 Bad Request**：请求无效，服务器无法理解。
- **401 Unauthorized**：请求需要身份验证。
- **403 Forbidden**：服务器拒绝请求。
- **404 Not Found**：请求的资源未找到。

### 5xx：服务器错误状态码

- **500 Internal Server Error**：服务器遇到错误，无法完成请求。
- **502 Bad Gateway**：网关或代理服务器接收到的响应无效。
- **503 Service Unavailable**：服务器暂时无法处理请求。

## HTTP 的特点与挑战

1. **无状态性**：每个 HTTP 请求都是独立的，可以通过 Cookie、Session 等机制维护客户端与服务器之间的状态。
2. **可扩展性**：可以通过请求头和响应头传递各种扩展信息。HTTP/2 提供多路复用、头部压缩和服务器推送等能力。
3. **安全性**：HTTP 本身不提供安全机制，通常使用基于 SSL/TLS 的 HTTPS 加密通信。
4. **性能优化**：
   - **持久连接**：HTTP/1.1 支持持久连接，避免每次请求都重新建立连接。
   - **缓存机制**：`Cache-Control`、`ETag` 等字段可以控制缓存策略，减少不必要的网络请求。
